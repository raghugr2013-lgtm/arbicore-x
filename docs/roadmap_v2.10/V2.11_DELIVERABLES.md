## 4. Architecture Impact

### Phase A — Market Intelligence (Slice 3)

Each of the 6 endpoints now reads exclusively from a canonical source; empty stores produce empty responses with no fabricated fallbacks.

```
GET /intelligence/recommendations
  top_routes    ← aggregate arbicore_opportunities by (buy_venue, sell_venue)
                  win_rate = approved / trials
                  mean_confidence
  top_chains    ← aggregate arbicore_opportunities by chain
  top_entities  ← get_entity_scorer().top()  (empty when unavailable)

GET /intelligence/decisions
  ← join arbicore_opportunity_journal events with arbicore_opportunities
  verdict map: operator_approved | discovery_promote → GO
               operator_rejected | discovery_dismiss → HARD_NO
               discovery_watch                        → SOFT_NO

GET /intelligence/calibration
  ← _CALIBRATION_REPO.get_active("confidence")
  empty → {available:false, buckets:[], n_samples:0}

GET /intelligence/models
  ← _CALIBRATION_REPO.list_recent("confidence") + _ADAPTIVE_WEIGHTS_REPO.get_active()
  promotions ← rows with `supersedes` present

GET /intelligence/certification
  ← services.execution.certification_review.latest_review()
  empty → {available:false}

GET /intelligence/entities
  ← get_entity_repo().count() + get_entity_scorer().top() + per-row repo.get(entity_id)
  vocabulary ← EntityType enum
```

### Phase B — Execution Planner (Slice 4)

The planner surface (already canonical since previous waves) is now session-cookie auth-gated and hardened against caller input errors.

```
Opportunity      (canonical: arbicore_opportunities)
      ↓
Execution Plan   (canonical: _EXECUTION_PLANNER + _EXECUTION_PLANS_REPO)
      ↓
Capital Alloc.   (canonical: _CAPITAL_ALLOCATOR + _CAPITAL_POLICY_REPO)
      ↓
Gas Estimation   (canonical: _GAS_ORACLE)
      ↓
MEV Routing      (canonical: _MEV_REGISTRY)
      ↓
TX Build         (canonical: encode_plan_head_call → balancer_v2 ✓;
                             aave_v3/uniswap deferred to Wave 7C+)
      ↓
Signing          (canonical: _LIVE_SIGNER gate ladder)
      ↓
Broadcast        (canonical: _LIMITED_LIVE_BROADCASTER; SHADOW by default,
                             LIMITED_LIVE gated by kill-switch + certification)
```

### Phase C — Auth Consolidation

Before: two auth patterns coexisted — Slice 1/1.1/2/3 used per-handler `await _require_operator_ctx(request, authorization)`, Slice 4 used `dependencies=[Depends(_require_operator_dep)]`.

After: one pattern — every protected route uses `dependencies=[Depends(_require_operator_dep)]`. Handler signatures no longer carry `request` / `authorization` params. Grep confirms exactly one `await _require_operator_ctx(` in `server.py` (inside the wrapper itself).

## 6. Behavioural Deltas (Frontend-visible)

Compared to v2.10.1:

1. **Market Intelligence** page now shows real routes/chains/entities derived from the canonical funnel (empty until real opps flow through).
2. **Intelligence Decisions** log reflects real operator actions (approve/reject/promote/dismiss/watch) from the journal, not the 6 hardcoded dec-00X rows.
3. **Intelligence Calibration** shows `available:false` until a real calibration model is fitted (was showing a synthetic 10-bucket identity mapping with n=931).
4. **Intelligence Models** list is empty until real models are trained (was showing 4 fake models + 3 fake promotions).
5. **Intelligence Certification** shows `available:false` until a shadow campaign completes (was showing a hardcoded 12-cycle NEEDS_MORE_DATA report).
6. **Intelligence Entities** list is empty until the entity_scorer receives data (was showing 10 fake wallet/pool entries).
7. **Planner** endpoints (adapters, plans, gas, mev, capital-policy, kill-switch, certification/stages) now require authentication. Anonymous callers receive 401. Frontend unchanged (already sends cookies).
8. **Planner** with incomplete swap-hop payloads now returns a proper `{error: 'ValueError: swap hop N missing required field(s): amount_in_wei, min_amount_out_wei'}` instead of a 500.

## 8. Missing Canonical Links Before Paper Validation & Limited Live

| # | What is missing | Why it blocks | Recommend fix in |
|---|---|---|---|
| 1 | **On-chain calldata encoder for aave_v3 and uniswap_v3 flash heads.** Wave 7C encoder only supports `balancer_v2`; `aave_v3` currently returns a documented `NotImplementedError`. | Limited-Live execution of aave-based flash-loan arbitrage cannot produce a signed transaction. Balancer route is available so a first LIMITED_LIVE campaign is still possible via Balancer flash heads. | v2.12 (or later) — requires deploying + verifying the arbitrage executor contract for each flash provider. |
| 2 | **Executor smart contract deployment on production chains.** The `encode_plan_head_call` machinery targets the ArbiCore executor contract, which must be deployed on `base` (initial chain) and verified on Basescan. | No LIMITED_LIVE broadcast can succeed without the executor. `broadcast(confirm:false)` returns a dry receipt; `confirm:true` would fail. | v2.12 — infra deploy task, not a code change. |
| 3 | **Certification review sample size ≥ 20 shadow cycles.** `certification_review.latest_review()` correctly returns `available:false` today; production sign-off requires 20 completed shadow cycles under the current thresholds. | LIMITED_LIVE is gated on `certification/run` producing a `SAFE_TO_ADVANCE` verdict. | Ongoing operational — as soon as v2.11 is on the VPS, shadow cycles begin accumulating. Not a code deliverable. |
| 4 | **Adaptive weights + calibration model fitting scheduler.** The repositories are in place (`_CALIBRATION_REPO`, `_ADAPTIVE_WEIGHTS_REPO`) but a fitting scheduler (cron / job) is not wired for production. | Intelligence panels remain empty (`available:false`) until models are fitted; this is cosmetic pre-live but blocks meaningful post-live calibration. | v2.12 or as an operational cron job — no schema changes required. |
| 5 | **Kill-switch operator UI wiring for engage/disengage.** Endpoints are auth-gated + canonical; frontend surfacing to be verified. | Operator must be able to engage kill-switch during LIMITED_LIVE. | v2.11.x follow-up (frontend-only, out of v2.11 scope). |

**Bottom line**: v2.11 completes the backend canonical pipeline all the way through Execution Planning. Paper Validation can start immediately after VPS deploy by running shadow cycles. Limited Live requires the executor contract deployment (#2) + Balancer-only calldata is sufficient for the first campaign (#1 waived for Balancer route). Items #3–#5 are operational/UX follow-ups, not blockers.
